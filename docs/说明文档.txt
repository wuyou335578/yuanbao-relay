【三】架构：为什么这么设计
────────────────────────────────────────────────────────────────

  ┌─────────────────────────────────────────────┐
  │ host (可执行文件)                            │
  │   · 创建窗口、驱动主循环                     │
  │   · 每 15 帧检查 game 动态库的 mtime         │
  │   · 变了 → dlclose 旧的 → dlopen 新的        │
  │   · 持有跨重载状态(time/frame/reload_count)  │
  │   · 画固定 HUD（用来区分宿主/game）          │
  └──────────────────┬──────────────────────────┘
                     │ dlopen / dlsym
  ┌──────────────────┴──────────────────────────┐
  │ game (动态库 .so)                            │
  │   · 就是"左边写代码"的那个文件               │
  │   · 导出 gameInit/Update/Draw/Unload         │
  │   · 改它 → 重新编译 → 自动重载               │
  └─────────────────────────────────────────────┘

■ 为什么不用原版 zig-raylib-hotreload 模板
  该模板依赖 Zig 包管理器从 github 拉取 raylib-zig，
  而本环境 github.com 是 403。
  改用本地 .path 依赖后，Zig 0.16 对 .path 依赖的 module 解析失败：
      error: no module named 'raylib'
  → 故改为直接用 raylib C 库 + @cImport，完全可控。

【四】环境重建步骤（新会话需重跑）
────────────────────────────────────────────────────────────────

■ 第 1 步：解除文件大小限制（关键！）
    ulimit -f unlimited
  不解除则超过 200MB 的文件写入会失败，
  这曾导致我误判为"磁盘不足"而删错文件。

■ 第 2 步：装系统库
    apt-get install -y xvfb scrot \
      libx11-dev libxcursor-dev libxrandr-dev libxinerama-dev \
      libxi-dev libgl1-mesa-dev libglu1-mesa-dev libasound2-dev

■ 第 3 步：装 Zig
    pip install ziglang -i https://mirrors.cloud.tencent.com/pypi/simple
    → Zig 0.16.0

■ 第 4 步：拿 raylib 源码（codeload 通道，github.com 是 403）
    curl -sL -o rl.tar.gz \
      "https://codeload.github.com/raysan5/raylib/tar.gz/refs/tags/6.0"
    tar xzf rl.tar.gz

■ 第 5 步：★ 编译 raylib 为【动态库】
    cd raylib-6.0/src
    make PLATFORM=PLATFORM_DESKTOP \
         GRAPHICS=GRAPHICS_API_OPENGL_33 \
         RAYLIB_LIBTYPE=SHARED -j$(nproc)
   ★ 必须是 SHARED，不能是 STATIC！
     用静态库会导致 host 和 game 各持一份 raylib 全局状态，
     一调用 DrawCircle 就段错误（实测踩过）。

■ 第 6 步：改 build.zig 里的路径
    RAYLIB_INC / RAYLIB_LIB 指向你的 raylib 目录

■ 第 7 步：编译 + 运行
    zig build
    export LD_LIBRARY_PATH=<raylib目录>:$LD_LIBRARY_PATH
    export DISPLAY=:99
    ./zig-out/bin/host

【六】本次踩的 5 个坑（都真实发生过）
────────────────────────────────────────────────────────────────

■ 坑 1：静态库导致段错误
  现象：Segmentation fault at address 0x18，崩在 DrawCircle
  原因：host 和 game 各自静态链接了一份 raylib，
        两边的全局状态（如渲染上下文）不一致
  解法：raylib 改用 RAYLIB_LIBTYPE=SHARED

■ 坑 2：无限递归
  现象：Segmentation fault，栈里全是 ci (game.zig)
  原因：批量替换 @intFromFloat(X) → ci(X) 时，
        ci 函数自身的 @intFromFloat 也被替换成了 ci
  解法：替换完检查函数自身定义

■ 坑 3：pkill -f 杀掉自己
  现象：脚本莫名其妙消失，卡死不动
  原因：pkill -f "zig-out/bin/host" 会匹配到
        正在执行这条命令的 shell 自身（命令行里含该字符串）
  解法：改用 pkill -x host（精确匹配进程名）

■ 坑 4：Zig 0.16 API 迁移
  老教程里的写法全部失效：
    artifact.addIncludePath()  →  module.addIncludePath()
    b.addSharedLibrary()       →  b.addLibrary(.{.linkage=.dynamic})
    linkSystemLibrary("x")     →  linkSystemLibrary("x", .{})
    LazyPath{.path=}           →  LazyPath{.cwd_relative=}
  这些是查 Build.zig 源码 + ZLS 补全确认的，不是猜的。

■ 坑 5（新发现，2026-09-17）：持久区 IO 会导致 zig 编译报 InputOutput
  现象：在 /data/workspace 下编译，报
        error: unable to load 'build.zig': InputOutput
        error: unable to load 'dependencies.zig': InputOutput
        但 build.zig 明明可读、空间也够
  原因：持久区(virtio_rw)文件系统与 zig 的 IO 路径有兼容问题
  解法：把项目复制到根分区(/bigworkspace 或 /tmp)再编译，
        并显式指定缓存目录：
          zig build --cache-dir /bigworkspace/hb/cache \
                    --global-cache-dir /bigworkspace/hb/gcache
        实测在根分区编译通过：host 9.5MB + libgame.so 9.4MB

■ 坑 6：对比基准被污染
  现象：v1 和 v2 两张图都是"改后"状态，对比看不出变化
  原因：后台脚本被误杀，finally 里的恢复逻辑没执行完，
        导致 game.zig 提前停留在已修改状态
  解法：验证前先确认基准文件的真实状态

【八】局限与已知问题（如实说明）
────────────────────────────────────────────────────────────────

■ game 内部状态重载会重置
  比如 game.zig 里的 var my_hue 会归零。
  需要跨重载保留的，要放进宿主的 SharedState。

■ 本次 AI 视觉只能"分类+取色+布局"，不能"看懂语义"
  ResNet50 把画面认成 "laptop / digital clock"，
  这是 ImageNet 类别的局限，不是渲染问题。
  但**取色和布局检测是精确的**，足够判断"对不对"。

■ 沙盒里的产物是 Linux 版
  你本机是 Windows，需要重新编译 raylib（Windows 用 MinGW 或 MSVC）。
  Zig 部分代码跨平台，main.zig 里的 dlopen 要换成 LoadLibrary。

■ Xvfb 是虚拟屏幕，性能靠软件渲染(llvmpipe)
  复杂 3D 场景会卡，2D/简单 3D 没问题。
